# Nick Metcalf — Colorist Portfolio

Live at **https://nrm461.github.io** · Design modeled on prodco.xyz/works

## How it works

Everything is generated from two files:

- `data/site.json` — site name, nav, contact page, which groups are visible
- `data/projects.json` — one entry per job (client, title, director, credits, vimeo link, etc.)

Edit either file, rebuild, publish. Never edit the HTML files directly — they get overwritten.

## Common tasks (or just ask Claude)

**Add a new spot** — credits, thumbs, stills, Vimeo upload and the entry, in one
command. Runs on the Mac Studio, where the masters are mounted:
```
ssh studio 'cd ~/dev/nrm461.github.io && git pull -q && python3 _build/add_spot.py Hills'
```
Then push the result from the Air (the Studio has no GitHub credentials yet):
```
git fetch ssh://studio/Users/nicholasmetcalf/dev/nrm461.github.io main && git merge --ff-only FETCH_HEAD && git push
```
It stages into `group: "hidden"` — the page builds but stays off the work grid until
you UNHIDE it in `/admin/`. Full runbook: **[docs/adding-a-spot.md](docs/adding-a-spot.md)**.

`_build/add_work.py` is the older, partial version of this (no Vimeo, no stills, no
staging) and is kept only for bulk backfills.

**Add a Vimeo link, fix a title or credit, hide a spot, reorder stills:** use
**`/admin/`**. It writes `data/projects.json` through the GitHub API and the Action
rebuilds the pages. Hand-editing the JSON still works, but admin is the maintained path.

**Don't run `_build/build_site.py` yourself** — the Action regenerates pages on push,
and a local rebuild collides with its own commit.

## The Deck (frame library)

`/deck/` (`deck/index.html`) is a separate, **hand-authored** single-file app — a
ShotDeck-style searchable library of stills from the graded work. It is **not**
generated by `build_site.py`, so unlike the rest of the site you edit its HTML
directly. Full details, design system, and the (browser-based) deploy method are
in `claude_project/04_deck.md`.

## Analytics

Page views come from **Umami** (cookieless, no consent banner). The script tag is
emitted by `page()` in `_build/build_site.py`, driven by `"analytics"` in
`data/site.json` — set `umami_id` to the site ID from the Umami dashboard. While it
is empty **nothing is emitted**, so a fresh clone and local previews stay untracked.

Plays are a custom event: `js/main.js` fires `trackEvent('play', {video, path})` when
a video facade is clicked, i.e. a real intent to watch. `trackEvent` is a no-op when
the Umami script isn't loaded (locally, or when a visitor blocks it).

`admin/` is deliberately untracked — it's hand-authored and it's Nick's own tool, so
counting those visits would pollute the numbers.

## Notes

- `token/git-token` holds the GitHub access token. It is git-ignored — never
  commit or share it.
- Font: IBM Plex Mono, self-hosted from `fonts/` under the OFL (see `fonts/OFL.txt`).
  It replaced the original site's licensed "OCRF" face, which was never obtained —
  every page now loads it via `--font` in `css/main.css`.
- Numbering (W001…) is assigned automatically to visible projects in
  chronological order at build time.
