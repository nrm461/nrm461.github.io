# WORKFLOW — how we work on this site

Treat this like an app project: every change is researched, built, verified, deployed, and **documented**. The documentation step is not optional — it's what lets the next chat continue without re-discovery.

## The loop for every change
1. **Research** — read the relevant docs + code first. Don't re-derive architecture; it's written down.
2. **Build** — edit the source of truth (data or generator/css/js), never generated HTML. Work in a fresh repo clone in the sandbox (`git clone --depth 1`), pinning `css/main.css`+`js/main.js` mtimes to the live `?v=` so rebuilds are byte-identical.
3. **Verify** — rebuild locally, `node --check` any JS, diff against the live file so only intended changes ship. For the deck, confirm a clean `build_deck.py` run == live (byte-identical) before and after.
4. **Deploy** — via the browser Contents API (below). Verify live (console errors, key markers). Note: GitHub Pages lags ~1 min after a push.
5. **Document** — update **CHANGELOG.md** (always), plus any reference doc that's now stale, plus project memory. Commit reusable scripts. THEN the task is done.

## Deploy mechanics (the only channel that works)
Neither the cloud sandbox nor the device bridge can `git push` (sandbox token is a placeholder; api.github.com is proxy-blocked; device_bash has no network). So **all commits go through the GitHub Contents API from a browser tab** on an nrm461.github.io origin, using `localStorage.getItem('ghtoken')`.
- Small text files (data, css, js, docs, deck/index.html): fetch current file → mutate in-browser → PUT with its `sha`. For large surgical edits, transfer only diff hunks (base64) and apply them in-page with a `count===1` uniqueness guard — don't paste whole large files through a tool call (the harness drops large output).
- **Big/binary assets** (deck frames, multi-MB data): exceed the browser API → Nick pushes from his Mac (`push_deck.sh`).
- **The Action:** —`.github/workflows/build.yml` runs `build_site.py` on pushes touching `data/** assets/thumbs/** assets/carousel/** _build/** css/** js/**`, and skips commits containing `[auto-build]`. So:
  - Changing site content/generator → commit WITHOUT `[auto-build]` to let the Action regenerate pages.
  - Committing generated output or source that doesn't change build_site output (e.g. deck files, docs) → prefix `[auto-build]` to skip a pointless rebuild.
  - `deck/` and `claude_project/` are NOT trigger paths → the Action never touches them; the deck is regenerated only by running `build_deck.py` yourself.

## The deck: single source of truth
`/deck/index.html` is generated by `_build/build_deck.py`, which imports `build_site.py` (so the shell/nav/footer are byte-identical to every page) and inlines `css/deck.css` + `js/deck.js` + the two `_build/deck_*.html` partials. Nav lives in `data/site.json` (inherited, no override). To change the deck: edit `js/deck.js`/`css/deck.css`/partials → `python3 _build/build_deck.py` → deploy `deck/index.html` → commit the source. Don't edit the inlined copy in `deck/index.html` directly except as the final PUT.

## Documentation discipline
- **CHANGELOG.md**: append a dated entry for every work session — what changed, why (decisions + rationale), what's live, what's still open. Newest on top. This is the "where we left off" record.
- **Reference docs (01/02/04)**: when a change makes them stale, fix them in the same session.
- **Project memory (MCP)**: keep the index (MEMORY.md) pointing at `claude_project/00_START_HERE.md`; mirror only highlights — the repo docs are canonical.
- **Reusable scripts → the repo.** Anything worth running again (frame extractors, migration one-offs, audits) gets committed to `_build/`. **Never leave tooling only in the sandbox** — sandboxes are wiped when the session ends, and a future chat cannot recover them (this is exactly how the deck frame-extractor was lost, 2026-07-18).
- Don't put secrets in docs (the token lives in `token/git-token`, gitignored — never commit or print it).

## Gotchas (learned the hard way)
- api.github.com / api.vimeo.com / IG CDNs are blocked in the sandbox → route through Claude-in-Chrome from an allowed page.
- Automation browser tabs load **backgrounded** → lazy images + `requestIdleCallback` are suspended and render can't be observed; verify visual/touch things (mobile layout, swipe, image sharpness) on Nick's actual phone, and rely on code+network checks otherwise.
- GitHub Pages caches; HTML can be ~10 min stale; images carry content-hash `?v=` busters.
- Generated-file merge conflicts: take remote data, re-run the mutation, rebuild — never `-X theirs` over `data/projects.json` (would drop admin edits).


## Version + handoff & local auto-sync (2026-07-18)
- **Version counter:** `claude_project/VERSION` holds `website YYYY.NNNN`. Read it at kickoff and LEAD the status with it. **Bump +1 on every push** (Contents API; new year → .0001). Not an Action trigger path.
- **Handoff:** at sign-off, print a handoff whose FIRST line is exactly `website YYYY.NNNN` (last pushed), alone, then a blank line, then Shipped/Open — so pasting it into a new chat seeds that chat's title.
- **Local auto-sync:** the Mac copy pulls origin via a LaunchAgent in `_local/` (30 min + login, ff-only). It needs Full Disk Access on /bin/zsh. For LIVE state read origin via the API, never the local copy.
