## Key data model (data/projects.json fields)
slug, client, title, director (IG handles preferred), category (Commercial / Music Video / Beauty / Long Form), vimeo (plain URL), credits (plain text, "Role: name @handle" lines; Dir/DP/Edit/Color/Prod Co float to a hero block automatically), group (`posted` = visible, `hidden` = /hidden/ page only, `rolled` = folded into a campaign, `pass`/`current` = fully off), selected + sel_order (landing grid), arch_order + delivered (archive is delivered-date order, newest first; undated go last), carousel (bool — assets/carousel/<slug>/00.jpg.. mobile swipe, 00 is hero), gallery (bool — carousel stills under credits, desktop only, complete rows of 3), children (campaign rollups: list of child slugs whose videos stack on one page), thumb at assets/thumbs/<slug>-{100,600,1600}.jpg.

## Workflow gotchas learned the hard way
- The sandbox blocks api.github.com / api.vimeo.com / IG CDNs — route those calls through the browser (Claude in Chrome) from an allowed page; GitHub's API accepts CORS from anywhere.
- Vimeo web session: get a JWT via `fetch('/_rv/jwt', {headers:{'x-requested-with':'XMLHttpRequest'}})` on vimeo.com, then call api.vimeo.com with `Authorization: jwt <token>`. JWTs expire — refresh on 401.
- Vimeo rate-limits scrapers with a "Verify to continue" wall — Nick must click it; never attempt CAPTCHAs.
- GitHub Pages caches aggressively; image URLs carry content-hash `?v=` busters generated at build time. HTML can be ~10 min stale.
- Generated-file merge conflicts: take the remote data, re-run your mutation, rebuild — don't `-X theirs` over data/projects.json.
