## How to deploy (critical)
Neither sandbox can `git push`: the cloud container has a placeholder token and `api.github.com` is blocked; the desktop bridge (`device_bash`) has no network. The ONLY working channel is the **GitHub Contents API from a browser tab on an `nrm461.github.io` origin**, using the token in `localStorage.ghtoken` (the `/admin/` page stores it). Pattern for text/JSON: fetch the file → mutate in-browser → PUT with its `sha`. Large/binary assets (deck frames, multi-MB data JSON) can't go this way — stage into Nick's local clone and he pulls+pushes. Full mechanics + code snippet: project memory `deploy.md`.

- Site pages are GENERATED by `_build/build_site.py` — never edit generated HTML; edit the data/generator and let the build Action regenerate. Commit ONLY source (`data/`, `css/`, `js/`, `_build/`); the Action rebuilds HTML on push and skips messages containing `[auto-build]`.
- `/deck/` is generated by `_build/build_deck.py` (reuses build_site's shell). Note: `claude_project/` and `deck/` are NOT Action trigger paths, so committing docs is harmless.

## Source of truth
`data/projects.json` on `origin/main`. Always pull before mutating; never resolve conflicts in a way that discards `admin:` commits.

## Project memory
Desktop project-memory holds topic notes (deploy, deck, categories, credits, archive-order, etc.) + a `MEMORY.md` index. If a memory note and these repo docs disagree, **the repo docs win** — update the note.


## Version + handoff & local auto-sync (2026-07-18)
- **Version counter:** `claude_project/VERSION` holds `website YYYY.NNNN`. Read it at kickoff and LEAD the status with it. **Bump +1 on every push** (Contents API; new year → .0001). Not an Action trigger path.
- **Handoff:** at sign-off, print a handoff whose FIRST line is exactly `website YYYY.NNNN` (last pushed), alone, then a blank line, then Shipped/Open — so pasting it into a new chat seeds that chat's title.
- **Local auto-sync:** the Mac copy pulls origin via a LaunchAgent in `_local/` (30 min + login, ff-only). It needs Full Disk Access on /bin/zsh. For LIVE state read origin via the API, never the local copy.
